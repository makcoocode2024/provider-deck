## Purpose

统一「配置里会写入哪个推理档位、这个档位从哪来」这句话在模型档位卡片与配置预览两处的措辞，使同一个模型在两个界面上读到的是同一句结论，不再需要用户自己判断哪句话可信。

## ADDED Requirements

### Requirement: 三种档位来源场景的统一措辞

系统 SHALL 把配置写出的档位来源归纳为三种场景，并在模型档位卡片与配置预览两处使用同一套说明措辞：

1. 命中用户自定义档位的匹配规则
2. 选中已探明的内置档位
3. 无匹配，回落全局兜底

同一模型在同一时刻，两处界面展示的场景 MUST 一致；场景名与档位名 MUST 来自同一份结算结果，MUST NOT 由两处各自推算。

#### Scenario: 命中自定义匹配档位

- **WHEN** 某模型命中了用户自定义档位的匹配规则
- **THEN** 模型档位卡片与配置预览 MUST 都表明写入的是该自定义档位，且来源是模型名称规则匹配
- **AND** 两处展示的档位名称 MUST 相同

#### Scenario: 选中内置档位

- **WHEN** 某模型已探明支持推理，用户选中了一个内置档位
- **THEN** 两处 MUST 都表明写入的是该内置档位
- **AND** 说明文字 MUST 表明这来自探测结论

#### Scenario: 回落全局兜底

- **WHEN** 某模型能力未探明且无任何匹配档位
- **THEN** 两处 MUST 都表明写入的是全局回退档
- **AND** 说明文字 MUST 明确标注"未探测"，且 MUST 提示用户可以自定义档位来适配这个模型

### Requirement: 设定与探测结论用词不混用

描述用户自己设定的档位时，说明文字 MUST NOT 使用"支持""兼容""已确认""已验证"等表达探测结论的词。描述探测结论时 MUST NOT 使用暗示是用户设定的措辞。

探测结论为不支持或已排除写档位的情况，MUST NOT 展示成兜底提示——用户设定推翻不了探测到的事实。

#### Scenario: 兜底档位的措辞

- **WHEN** 界面展示一个来自用户设定的兜底档位
- **THEN** 该处文字 MUST 含有表明未经探测的标注
- **AND** MUST NOT 出现"支持"或"已确认"

#### Scenario: 探测到不支持

- **WHEN** 某模型已探明不支持推理
- **THEN** 两处 MUST NOT 展示兜底档位提示
- **AND** MUST 表明依探测结论省略档位

### Requirement: 实时请求与配置写入的差别必须写明

凡是展示档位将被写入的地方，说明文字 MUST 表明该档位只作用于配置文件写出，实时业务请求不会因此附带推理参数。

#### Scenario: 兜底场景的作用范围说明

- **WHEN** 界面展示未探明模型的兜底档位
- **THEN** 说明文字 MUST 表明这仅用于写入配置文件
- **AND** MUST 表明实时请求仍不发送推理参数

### Requirement: 提示文字不暴露密钥

两处界面上的任何档位说明、来源说明、错误提示 MUST NOT 包含 API 密钥的完整值或可识别片段。

#### Scenario: 探测失败的错误提示

- **WHEN** 探测或预览过程出错并把错误展示给用户
- **THEN** 提示文字 MUST NOT 包含 API 密钥内容
