## Purpose

让正式发布包的版本号在打包流程中自动前进一个补丁号，并保证所有携带版本号的文件始终指向同一个值，避免出现"两次发布同一个版本号"或"同一个包自称两个版本号"。日常开发不受影响。

## ADDED Requirements

### Requirement: 仅正式打包触发补丁号自增

系统 SHALL 只在正式发布打包流程中自增版本号。日常开发命令（开发服务器、类型检查、单元测试、lint、E2E）MUST NOT 修改任何文件中的版本号。

自增 MUST 以 `package.json` 的 version 为唯一输入来源，MUST 只递增补丁号，MUST NOT 改动主版本号与次版本号。

#### Scenario: 正式打包

- **WHEN** 正式打包流程执行到自增步骤
- **THEN** 补丁号 MUST 在原值上加一
- **AND** 主版本号与次版本号 MUST 保持原值

#### Scenario: 日常开发

- **WHEN** 执行开发服务器或任一测试闸门命令
- **THEN** 版本号相关文件 MUST 保持字节不变

#### Scenario: 版本号不是三段式数字

- **WHEN** 现有版本号带预发布标识、构建元数据，或不是三段纯数字
- **THEN** 自增 MUST 中止并报错，MUST NOT 猜测应当递增哪一段

### Requirement: 全部携带版本号的文件保持对齐

自增 SHALL 把新版本号同步写入所有携带该版本号的文件。写入 MUST 是全有或全无：任一文件无法按预期改写时，MUST NOT 留下部分文件已改、部分未改的状态。

自增前 MUST 确认所有目标文件当前版本号一致；不一致时 MUST 中止，MUST NOT 用自己算出的值覆盖分歧。

#### Scenario: 四处版本号一致

- **WHEN** 所有目标文件当前报告同一个版本号
- **THEN** 全部文件 MUST 被改写为新版本号
- **AND** 改写后由独立的版本核对流程再次确认一致

#### Scenario: 目标文件之间版本号不一致

- **WHEN** 任意两个目标文件报告的版本号不同
- **THEN** 自增 MUST 中止并列出各文件的当前值
- **AND** MUST NOT 写入任何文件

#### Scenario: 某个文件缺少预期的版本号字段

- **WHEN** 目标文件中找不到应当改写的版本号位置
- **THEN** 自增 MUST 中止并指明是哪个文件
- **AND** MUST NOT 写入任何文件

### Requirement: 自增发生在测试闸门通过之后

自增 SHALL 排在打包流程的测试闸门之后。任一测试闸门失败时，版本号 MUST 保持原值，源文件 MUST 零改动。

#### Scenario: 测试闸门失败

- **WHEN** 单元测试、类型检查或 lint 中任意一项失败
- **THEN** 打包 MUST 中止
- **AND** 版本号相关文件 MUST 保持原值

#### Scenario: 同一版本重跑打包

- **WHEN** 调用方显式要求跳过自增
- **THEN** 版本号 MUST 保持原值
- **AND** 版本一致性核对 MUST 照常执行

### Requirement: 新版本号写入变更日志顶部

自增 SHALL 在变更日志文件顶部插入本次版本的小节，最新版本在最上方。插入 MUST 保留已有内容。

日志正文 MUST NOT 由脚本推测或编造变更摘要；未由调用方提供摘要时 MUST 留下明确的待填写占位。

#### Scenario: 变更日志已存在

- **WHEN** 变更日志文件已有内容
- **THEN** 新小节 MUST 位于所有既有版本小节之前
- **AND** 既有内容 MUST 逐字保留

#### Scenario: 变更日志尚不存在

- **WHEN** 变更日志文件不存在
- **THEN** MUST 创建该文件并写入本次版本小节

### Requirement: 输出可核对的版本变更日志行

自增 SHALL 向控制台输出一行包含旧版本号与新版本号的说明，供操作者当场核对。

输出 MUST NOT 包含 API 密钥或任何鉴权字段片段。

#### Scenario: 自增成功

- **WHEN** 自增完成
- **THEN** 控制台 MUST 打印旧版本号与新版本号
- **AND** 新版本号 MUST 可被打包流程后续步骤读取，用于命名产物目录与产物文件
